RAKE OBF V1.1
=============

Обфускатор Lua 5.1 - 5.4 на чистом Python.

Что нового в 1.1
----------------
* В начале каждого результата стоит строка:
      ---- RAKE OBF V1.1 ----
  (после shebang, если он есть в исходнике).
* Размер результата по умолчанию доводится до 4x от размера исходника:
  1 МБ на входе -> примерно 4 МБ на выходе. Для маленьких файлов
  коэффициент может быть больше, потому что код обфускации сам по себе
  занимает место.
* Строки шифруются по отдельности: у каждой строки свой ключ, соль и
  смещение. Длинные строки режутся на части и собираются в рантайме.
* Числа (включая hex) заменяются более длинными арифметическими
  выражениями. Логические true/false тоже маскируются.
* Локальные переменные, параметры, переменные циклов и метки/goto
  переименовываются.
* Добавлены decoy-блоки (ложные ветки с длинными строками), чтобы
  добить нужный размер без роста байткода и без затрат в рантайме.
* Загрузчик --pack стал сложнее: потоковый ключ, соль, случайное имя
  чанка, полезная нагрузка в base64.

Использование
-------------
Из папки, где лежит папка luaobf:

    python -m luaobf input.lua -o output.lua

С шифрованием всего чанка (нужен load/loadstring):

    python -m luaobf input.lua --pack -o output.lua

С отчётом:

    python -m luaobf input.lua -o output.lua --stats

Полезные ключи
--------------
    --ratio 4.0       желаемый коэффициент размера (по умолчанию 4.0)
    --ratio 1         не добавлять padding
    --no-padding      то же самое
    --pack            зашифровать весь чанк и добавить загрузчик
    --pretty          многострочный вывод (для отладки)
    --no-rename       не переименовывать locals
    --no-strings      не шифровать строки
    --no-numbers      не трогать числа
    --no-bools        не трогать true/false
    --seed N          детерминированный результат
    --verify          выполнить исходник и результат в Lua и сравнить вывод
    --stats           показать статистику

Пример для 1 МБ файла:

    python -m luaobf script.lua -o script.obf.lua --stats

Ожидаемый вывод в статистике:

    luaobf: ... -> 4194304 bytes (4.00x)

Примечания
----------
* --pack требует load/loadstring в среде выполнения. В обычном Lua 5.1
  это loadstring, в 5.2+ load.
* --verify запускает настоящий интерпретатор lua с PATH. Скрипты,
  которым нужен Roblox (game, Instance и т.п.), проверять так нельзя.
* Если исходник уже даёт больше 4x после обфускации (например, очень
  много бинарных строк), файл не уменьшается: коэффициент будет выше.
* Padding сделан в виде мёртвых веток с длинными строками. Он почти не
  тратит байткод и не выполняется, но файл и память парсера занимает.
* Для Luau/Roblox с нестандартным синтаксисом (continue, +=, типы)
  этот обфускатор не предназначен: он разбирает Lua 5.1 - 5.4.
